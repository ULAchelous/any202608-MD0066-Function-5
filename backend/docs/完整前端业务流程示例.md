# 好好说：完整前端业务流程模拟

> 示例场景：用户在家庭群看到“隔夜菜一定会致癌，赶紧转给家人”，希望先核验，再生成一段适合私发给妈妈的话。

## 一、完整流程总览

```text
0. 页面初始化
   GET /health
        ↓
1. 用户输入内容（纯前端，不请求接口）
        ↓
2. 提取核心主张
   POST /api/extract
        ↓
3. 用户确认主张并选择沟通对象（纯前端，不请求接口）
        ↓
4. 权威核验并生成沟通策略
   POST /api/verify
        ↓
5. 用户选择输出风格（纯前端，不请求接口）
        ↓
6. 生成最终沟通方案
   POST /api/card
        ↓
7. 前端组合并展示最终方案（纯前端）
```

后端一共请求 4 次：

| 顺序 | 接口 | 是否必须 | 作用 |
|---:|---|---:|---|
| 1 | `GET /health` | 推荐 | 判断是否真实模式、图片/视频能力是否可用 |
| 2 | `POST /api/extract` | 是 | 从原始输入中提取可核验的核心主张 |
| 3 | `POST /api/verify` | 是 | 核验主张并生成风险、来源、沟通策略 |
| 4 | `POST /api/card` | 是 | 将核验结果转成可直接发送的沟通方案 |

## 二、逐步模拟

## 第 0 步：页面初始化，检查后端能力

### 前端做什么

页面加载后调用健康检查，用它决定：

- 是否显示“演示模式”；
- 是否开放图片识别；
- 是否允许处理微信公众号视频；
- 是否提示后端服务异常。

### 请求接口

```http
GET http://127.0.0.1:8000/health
```

没有请求参数，没有请求体。

### 模拟返回

```json
{
  "status": "ok",
  "ffmpeg_available": true,
  "luna_configured": true,
  "tavily_configured": true,
  "mock_mode": false
}
```

### 前端使用哪些字段

| 返回字段 | 前端用途 |
|---|---|
| `status` | 判断后端进程是否正常响应 |
| `mock_mode` | 为 `true` 时显示“演示模式，可能含模拟数据” |
| `luna_configured` | 为 `false` 时禁用图片识别或提示能力受限 |
| `tavily_configured` | 为 `false` 时提示核验来源可能是模拟数据 |
| `ffmpeg_available` | 为 `false` 时提示公众号视频暂不可处理 |

### 页面状态

```ts
health = response;
backendReady = response.status === "ok";
isDemoMode = response.mock_mode;
```

## 第 1 步：用户输入原始内容

### 前端做什么

让用户选择输入方式：

1. 粘贴文字；
2. 上传聊天截图；
3. 粘贴微信公众号链接。

本示例选择“粘贴文字”：

```text
震惊！隔夜菜一定会致癌，专家紧急提醒：赶紧倒掉，马上转给家人！
```

### 是否请求接口

**不请求。** 这一步只在前端保存用户输入。

### 页面状态

```ts
sourceType = "text";
sourceContent = "震惊！隔夜菜一定会致癌，专家紧急提醒：赶紧倒掉，马上转给家人！";
```

### 三种输入如何映射

| 用户输入方式 | `type` | `content` |
|---|---|---|
| 文字 | `text` | 原始文字 |
| 截图 | `image` | 图片 Data URL，例如 `data:image/png;base64,...` |
| 公众号链接 | `wechat_url` | `https://mp.weixin.qq.com/...` |

## 第 2 步：提取核心主张

### 前端做什么

用户点击“提取主张”后，将第 1 步保存的内容提交给后端。

### 请求接口

```http
POST http://127.0.0.1:8000/api/extract
Content-Type: application/json
```

### 传入参数

```json
{
  "type": "text",
  "content": "震惊！隔夜菜一定会致癌，专家紧急提醒：赶紧倒掉，马上转给家人！"
}
```

参数说明：

| 参数 | 类型 | 必填 | 本例值 |
|---|---|---:|---|
| `type` | `text \| image \| wechat_url` | 是 | `text` |
| `content` | `string` | 是 | 用户输入的完整原文 |

### 模拟返回

```json
{
  "claim": "隔夜菜一定会致癌",
  "original_evidence": [
    "隔夜菜一定会致癌"
  ],
  "patterns": [
    "夸大因果",
    "恐惧驱动",
    "冒用权威"
  ],
  "article_title": null,
  "article_author": null,
  "source_kind": null,
  "video_id": null
}
```

### 前端使用哪些字段

| 返回字段 | 前端用途 |
|---|---|
| `claim` | 填入“待核验主张”输入框，供用户确认或编辑；下一步传给 `/api/verify` |
| `original_evidence` | 展示“系统从原文中识别到的证据” |
| `patterns` | 展示“夸大因果”“恐惧驱动”等风险标签 |
| `article_title` | 公众号场景展示文章标题 |
| `article_author` | 公众号场景展示作者或公众号名 |
| `source_kind` | 区分公众号图文或视频 |
| `video_id` | 可用于前端调试或业务追踪；普通内容可能为 `null` |

### 页面状态

```ts
extraction = response;
editableClaim = response.claim;
```

### 前端做什么

1. 确认或编辑待核验主张；
2. 选择沟通对象；
3. 选择当前关系状态。

```text
沟通对象：妈妈
关系状态：最近有过争执
```

### 是否请求接口

**不请求。** 这一步只是让用户修正 AI 提取结果，并收集核验所需上下文。

### 页面状态

```ts

target = "mother";
relationshipState = "recent_conflict";
```

推荐前端选项映射：

| UI 文案 | 传给后端的值 |
|---|---|
| 妈妈 | `mother` |
| 爸爸 | `father` |
| 爷爷奶奶/外公外婆 | `grandparent` |
| 其他长辈 | `elder` |

| UI 文案 | 传给后端的值 |
|---|---|
| 关系正常 | `normal` |
| 最近有争执 | `recent_conflict` |
| 关系紧张 | `tense` |
| 已经在群里传播 | `group_spreading` |

## 第 7 步：前端展示最终方案

### 是否请求接口

**不请求。** 前端使用第 4 步和第 6 步的数据组合页面。

### 建议页面结构

```text
┌──────────────────────────────────────┐
│ 安心核验卡：这条说法不太准确          │
│                                      │
│ 妈，我知道你发这个是担心我们吃得不健康。│
│                                      │
│ 事实：隔夜不等于一定致癌，保存方式和   │
│ 时间更关键。                          │
│                                      │
│ 建议：剩菜尽快冷藏，吃前充分加热；     │
│ 拿不准就不吃。                        │
│                                      │
│ 以后看到类似消息，我们一起查一查。     │
│                                      │
│ [复制文案] [查看来源] [切换群公告版]   │
└──────────────────────────────────────┘
```

### 推荐同时展示

- 核验结论：`report.verdict`
- 风险等级：`report.risk_level`
- 沟通渠道与原因：`report.communication.channel/reason`
- 最终可发送文案：`card.greeting/fact/suggestion/self_verify/closing`
- 权威来源：`card.sources`
- 医疗免责声明：`card.medical_notice`

### 复制给长辈的纯文本拼接

```ts
function buildShareText(card: VerificationCard): string {
  return [
    card.title,
    card.greeting,
    card.fact,
    card.suggestion,
    card.self_verify,
    card.closing,
    card.medical_notice,
  ]
    .filter(Boolean)
    .join("\n\n");
}
```

## 四、前端状态模型建议

```ts
interface FlowState {
  step: "input" | "extract" | "confirm" | "verify" | "style" | "result";
  loading: boolean;
  error: string | null;

  health: HealthResponse | null;

  sourceType: "text" | "image" | "wechat_url";
  sourceContent: string;

  extraction: ClaimExtraction | null;
  confirmedClaim: string;

  target: string;
  relationshipState: string;

  report: VerificationReport | null;

  cardStyle: "elder" | "group_notice";
  card: VerificationCard | null;
}
```

调用顺序伪代码：

```ts
async function completeFlow(state: FlowState) {
  state.health = await api.health();

  state.extraction = await api.extract({
    type: state.sourceType,
    content: state.sourceContent,
  });

  // 在真实 UI 中暂停，等待用户确认或修改。
  state.confirmedClaim = state.extraction.claim;

  state.report = await api.verify({
    claim: state.confirmedClaim,
    target: state.target,
    relationship_state: state.relationshipState,
  });

  state.card = await api.createCard({
    claim: state.report.claim,
    verdict: state.report.verdict,
    risk_level: state.report.risk_level,
    summary: state.report.summary,
    target: state.target,
    style: state.cardStyle,
    sources: state.report.sources,
  });
}
```

## 五、关键异常分支

| 发生步骤 | 情况 | 前端处理 |
|---|---|---|
| 健康检查 | 服务无法连接 | 阻止继续，提示检查 Base URL 或后端服务 |
| 健康检查 | `mock_mode=true` | 允许演示，但持续显示“模拟数据”标记 |
| 输入图片 | `luna_configured=false` | 禁用图片提交或提示配置视觉模型 |
| 输入公众号视频 | `ffmpeg_available=false` | 提前提示视频不可处理，可引导复制正文或上传截图 |
| 提取主张 | `422` | 提示输入格式、公众号链接或文章读取问题 |
| 提取主张 | `502/503` | 提示模型或视频处理暂不可用 |
| 核验 | `sources=[]` 或 `verdict=uncertain` | 展示“证据不足”，不要包装成确定结论 |
| 任意请求 | `detail` 为数组 | 合并各字段校验错误展示 |
| 任意请求 | 返回纯文本 500 | 使用统一兜底错误文案 |
| 卡片生成 | 文案不合适 | 允许用户编辑，或切换风格后重新请求 `/api/card` |

## 六、前端负责人最需要记住的 6 点

1. 完整链路是 `/health → /api/extract → /api/verify → /api/card`。
2. 用户输入、确认主张、选择对象和选择风格都只是前端状态，不需要额外接口。
3. `/api/extract` 的 `claim` 不应直接盲目进入核验，最好先让用户确认。
4. `/api/verify` 的核心输出要原样传给 `/api/card`，尤其是 `sources`。
5. 公众号视频是长请求，当前没有 SSE；要提供持续 Loading 和较长超时。
6. `mock_mode=true` 时必须明确标记演示数据，不能当作真实医学结论。
