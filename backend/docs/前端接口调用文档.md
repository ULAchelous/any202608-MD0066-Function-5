# 好好说 Backend 前端接口调用文档

> 面向前端负责人。本文档基于当前后端代码编写，接口版本为 `0.1.0`。

## 1. 这套接口能做什么

前端可以用这套接口完成一条完整的“健康信息核验 + 沟通建议”链路：

```text
用户粘贴公众号链接 / 输入文字 / 上传截图
              ↓
       提取核心健康主张
              ↓
  检索权威来源并判断可信度与风险
              ↓
  生成适合私发长辈或发家庭群的核验卡
```

具体能力：

1. **提取主张**：从文本、截图、微信公众号纯图文或内嵌视频中提取核心健康说法，并识别“夸大因果”“恐惧驱动”等话术特征。
2. **核验主张**：搜索权威来源，给出可信度、风险等级、证据来源和更合适的沟通方案。
3. **生成核验卡**：生成适合私发长辈的温和文案，或适合家庭群发布的中性科普公告。
4. **检查服务状态**：判断服务、FFmpeg、模型和搜索服务是否就绪，以及当前是否在 Mock 演示模式。

## 2. 接入信息

### 2.1 Base URL

开发环境默认约定：

```text
http://<后端服务器地址>:8000
```

本机联调示例：

```text
http://127.0.0.1:8000
```

后端启动命令中的端口可修改，因此部署后请通过前端环境变量配置 Base URL，不要写死：

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

### 2.2 在线调试文档

后端启动后可访问：

- Swagger UI：`{BASE_URL}/docs`
- OpenAPI JSON：`{BASE_URL}/openapi.json`
- ReDoc：`{BASE_URL}/redoc`

### 2.3 通用协议

- 所有业务接口使用 HTTP。
- 所有 POST 接口使用 `Content-Type: application/json`。
- 当前没有登录、Token、Cookie 或其他鉴权要求。
- 当前允许跨域 JSON 请求，但未启用 Cookie 凭据。
- 当前没有 WebSocket、SSE、文件表单上传和任务进度接口。
- 成功状态码均为 `200`。

## 3. 推荐前端调用流程

### 第一步：检查运行状态

页面初始化或用户首次开始核验时调用：

```text
GET /health
```

如果 `mock_mode=true`，必须明显提示用户“当前为演示模式，结果可能包含模拟数据”。

### 第二步：提取核心主张

```text
POST /api/extract
```

支持三种输入：

- 用户直接输入文字：`type=text`
- 用户上传截图：前端转成 Base64/Data URL，`type=image`
- 用户粘贴公众号链接：`type=wechat_url`

提取后建议让用户确认或编辑 `claim`，再进入核验。

### 第三步：核验主张

```text
POST /api/verify
```

返回可信度、风险等级、权威来源，以及建议采用私聊、群公告等哪种沟通方式。

### 第四步：生成核验卡

```text
POST /api/card
```

将核验接口返回的 `claim`、`verdict`、`risk_level`、`summary` 和 `sources` 传入，可生成：

- `elder`：适合私发长辈；
- `group_notice`：适合发家庭群或群公告。

> 后端不保存会话或上一步结果。每个请求都必须携带本次需要的数据，没有可复用的任务 ID。

## 4. 接口一览

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 检查服务、外部依赖和 Mock 状态 |
| `POST` | `/api/extract` | 从文字、图片或公众号内容中提取核心主张 |
| `POST` | `/api/verify` | 核验主张并生成来源、风险与沟通建议 |
| `POST` | `/api/card` | 生成长辈版或群公告版核验卡 |

## 5. GET /health

### 用途

检查后端是否可访问，以及模型、搜索服务和视频抽帧环境是否就绪。

### 请求

```http
GET /health
```

无请求参数和请求体。

### 成功响应

```json
{
  "status": "ok",
  "ffmpeg_available": true,
  "luna_configured": true,
  "tavily_configured": true,
  "mock_mode": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | `string` | 固定为 `ok`，只说明后端进程能响应 |
| `ffmpeg_available` | `boolean` | 能否处理公众号视频抽帧 |
| `luna_configured` | `boolean` | 文本/视觉模型是否已配置 |
| `tavily_configured` | `boolean` | 权威来源搜索服务是否已配置 |
| `mock_mode` | `boolean` | 任一外部提供者未完整配置时为 `true` |

### 前端处理建议

- `status=ok` 不代表全部能力可用，需要同时查看其他字段。
- `ffmpeg_available=false`：文本、图片、公众号纯图文仍可能可用，但公众号视频会失败。
- `luna_configured=false`：图片识别不可用；部分其他接口会使用 Mock。
- `mock_mode=true`：页面必须显示“演示模式”标记，不要把模拟来源当作真实核验结论。

## 6. POST /api/extract

### 用途

从输入内容中提取核心健康主张、原始证据和话术特征。

### 请求结构

```ts
type ExtractSourceType = "text" | "image" | "wechat_url";

interface ExtractRequest {
  type: ExtractSourceType;
  content: string;
}
```

| 字段 | 必填 | 规则 |
|---|---:|---|
| `type` | 是 | 只能为 `text`、`image`、`wechat_url` |
| `content` | 是 | 至少 1 个字符；具体格式由 `type` 决定 |

### 6.1 提取文本

```http
POST /api/extract
Content-Type: application/json
```

```json
{
  "type": "text",
  "content": "震惊！隔夜菜一定会致癌，赶紧转给家人！"
}
```

注意：后端模型当前最多使用前 12000 个字符。建议前端限制输入长度并去除纯空白内容。

### 6.2 提取图片

后端不接收 `multipart/form-data`，前端需要先将图片转成 Data URL 或 Base64，再放入 JSON：

```json
{
  "type": "image",
  "content": "data:image/png;base64,iVBORw0KGgoAAA..."
}
```

后端可识别的开头：

- `data:image/`
- `iVBOR`（常见 PNG Base64）
- `/9j/`（常见 JPEG Base64）

建议前端：

- 仅允许 PNG、JPEG、WebP；
- 上传前压缩图片；
- 建议限制在约 4 MB 以内；
- 不要上传包含敏感头像、群名、电话等信息的完整截图；
- 优先使用标准 Data URL，避免裸 Base64 的格式歧义。

浏览器转换示例：

```ts
function fileToDataUrl(file: File): Promise<string> {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(String(reader.result));
    reader.onerror = () => reject(reader.error);
    reader.readAsDataURL(file);
  });
}
```

### 6.3 提取微信公众号内容

```json
{
  "type": "wechat_url",
  "content": "https://mp.weixin.qq.com/s/..."
}
```

只支持：

```text
https://mp.weixin.qq.com/...
```

后端会自动判断：

- 纯图文文章：提取正文后交给文本模型；
- 内嵌视频文章：下载视频、均匀抽帧后交给视觉模型。

公众号视频处理可能需要较长时间，前端应持续显示 Loading，不要设置过短超时。当前没有流式进度。

### 成功响应

```ts
interface ClaimExtraction {
  claim: string;
  original_evidence: string[];
  patterns: string[];
  article_title: string | null;
  article_author: string | null;
  source_kind: string | null;
  video_id: string | null;
}
```

示例：

```json
{
  "claim": "隔夜菜一定会致癌",
  "original_evidence": [
    "隔夜菜一定会致癌"
  ],
  "patterns": [
    "夸大因果",
    "恐惧驱动"
  ],
  "article_title": null,
  "article_author": null,
  "source_kind": null,
  "video_id": null
}
```

| 字段 | 说明 |
|---|---|
| `claim` | 提取出的核心健康主张 |
| `original_evidence` | 原文、字幕或画面中的直接证据 |
| `patterns` | 识别到的话术模式 |
| `article_title` | 公众号标题；普通文本/图片通常为 `null` |
| `article_author` | 公众号作者或公众号名；没有则为 `null` |
| `source_kind` | 公众号场景当前可能为 `wechat_article` 或 `wechat_video`；其他场景可能为 `null` |
| `video_id` | 微信视频 ID；没有则为 `null` |

> `patterns` 和 `source_kind` 不是严格枚举，前端遇到未知值时应原样显示或使用兜底标签。

### 常见错误

| 状态码 | 场景 |
|---|---|
| `422` | 请求字段错误、图片格式错误、公众号链接不受支持、公众号内容无法读取、视频下载失败 |
| `502` | 模型未配置、模型调用失败或未返回合法 JSON |
| `503` | 未安装 FFmpeg、视频抽帧超时或没有提取到画面 |
| `500` | 未被业务层捕获的服务异常 |

## 7. POST /api/verify

### 用途

核验一条健康主张，返回可信度、风险、权威来源和沟通建议。

### 请求结构

```ts
interface VerifyRequest {
  claim: string;
  target?: string;
  relationship_state?: string;
}
```

| 字段 | 必填 | 默认值 | 规则/建议值 |
|---|---:|---|---|
| `claim` | 是 | 无 | 2～500 个字符 |
| `target` | 否 | `elder` | 最多 30 字符；建议 `mother`、`father`、`grandparent`、`elder` |
| `relationship_state` | 否 | `normal` | 最多 30 字符；建议 `normal`、`recent_conflict`、`tense`、`group_spreading` |

> `target` 和 `relationship_state` 在后端是普通字符串，不是严格枚举。建议前端固定选项，避免拼写不一致影响模型理解。

### 请求示例

```json
{
  "claim": "隔夜菜一定会致癌",
  "target": "mother",
  "relationship_state": "recent_conflict"
}
```

### 成功响应

```ts
interface SourceItem {
  title: string;
  url: string;
  publisher: string;
  evidence: string;
}

interface Communication {
  channel: string;
  reason: string;
  opening: string;
  fact: string;
  suggestion: string;
}

interface VerificationReport {
  claim: string;
  verdict: string;
  risk_level: string;
  summary: string;
  patterns: string[];
  sources: SourceItem[];
  communication: Communication;
  medical_notice: string;
}
```

示例：

```json
{
  "claim": "隔夜菜一定会致癌",
  "verdict": "misleading",
  "risk_level": "low",
  "summary": "现有证据不支持把隔夜菜与必然致癌直接画等号。",
  "patterns": [
    "夸大因果",
    "恐惧驱动"
  ],
  "sources": [
    {
      "title": "权威来源标题",
      "url": "https://example.org/article",
      "publisher": "example.org",
      "evidence": "与本次主张相关的证据摘要"
    }
  ],
  "communication": {
    "channel": "private_chat",
    "reason": "最近有冲突，优先私聊，避免公开否定。",
    "opening": "妈，我知道你是担心我们的健康。",
    "fact": "这个说法把有条件的风险说得太绝对了。",
    "suggestion": "我们一起看看权威来源，以后先核实再转发。"
  },
  "medical_notice": "内容仅供健康信息核验，不能替代医生诊断。"
}
```

### 关键字段建议值

以下值由模型提示词约定，但后端 Schema 没有强制枚举。前端必须提供未知值兜底。

`verdict`：

| 值 | 前端文案建议 |
|---|---|
| `credible` | 基本可信 |
| `misleading` | 有误导性 |
| `uncertain` | 证据不足 |
| 其他 | 待判断 |

`risk_level`：

| 值 | 前端文案建议 |
|---|---|
| `low` | 低风险 |
| `medium` | 中风险 |
| `high` | 高风险 |
| 其他 | 未知风险 |

`communication.channel`：

| 值 | 含义 |
|---|---|
| `private_chat` | 私聊沟通 |
| `family_group` | 家庭群说明 |
| `via_relative` | 请其他亲属转达 |
| `no_reply` | 暂不回应 |
| 其他 | 按 `reason` 展示 |

### 前端展示建议

- `sources` 可能为空，证据不足时要允许展示“暂未找到足够来源”。
- 外链只允许 `http:` 和 `https:`，并使用 `rel="noopener noreferrer"`。
- 不要把来源标题或证据摘要作为 HTML 直接插入页面。
- 核验结果不能替代医生诊断，始终展示 `medical_notice`。
- 当 `mock_mode=true` 时，来源可能是固定的演示占位数据。

### 常见错误

| 状态码 | 场景 |
|---|---|
| `422` | `claim` 长度不合法，或其他请求字段校验失败 |
| `502` | Luna 模型调用失败 |
| `500` | Tavily 超时、限流、网络错误，或未捕获的模型结构错误等 |

## 8. POST /api/card

### 用途

根据核验结果生成适合分享的短句核验卡。

该接口不强制依赖 `/api/verify`，只要请求体完整即可单独调用。但推荐直接复用核验接口返回的数据。

### 请求结构

```ts
type CardStyle = "elder" | "group_notice";

interface CardRequest {
  claim: string;
  verdict?: string;
  risk_level?: string;
  summary?: string;
  target?: string;
  style?: CardStyle;
  sources?: SourceItem[];
}
```

| 字段 | 必填 | 默认值 | 规则 |
|---|---:|---|---|
| `claim` | 是 | 无 | 2～500 个字符 |
| `verdict` | 否 | `uncertain` | 建议直接使用 `/api/verify` 返回值 |
| `risk_level` | 否 | `low` | 建议直接使用 `/api/verify` 返回值 |
| `summary` | 否 | 空字符串 | 最多 1000 字符 |
| `target` | 否 | `elder` | 最多 30 字符 |
| `style` | 否 | `elder` | 严格为 `elder` 或 `group_notice` |
| `sources` | 否 | `[]` | 建议使用 `/api/verify` 返回的来源 |

### 长辈版请求示例

```json
{
  "claim": "隔夜菜一定会致癌",
  "verdict": "misleading",
  "risk_level": "low",
  "summary": "现有证据不支持把隔夜菜与必然致癌直接画等号。",
  "target": "mother",
  "style": "elder",
  "sources": [
    {
      "title": "权威来源标题",
      "url": "https://example.org/article",
      "publisher": "example.org",
      "evidence": "证据摘要"
    }
  ]
}
```

### 群公告版请求示例

```json
{
  "claim": "隔夜菜一定会致癌",
  "verdict": "misleading",
  "risk_level": "low",
  "summary": "现有证据不支持把隔夜菜与必然致癌直接画等号。",
  "style": "group_notice",
  "sources": []
}
```

### 成功响应

```ts
interface VerificationCard {
  title: string;
  greeting: string;
  fact: string;
  suggestion: string;
  self_verify: string;
  closing: string;
  sources: SourceItem[];
  medical_notice: string;
}
```

示例：

```json
{
  "title": "安心核验卡：这条说法不太准确",
  "greeting": "妈，我知道你发这个是为了我们好。",
  "fact": "现有证据不支持必然致癌的说法。",
  "suggestion": "剩菜及时冷藏，吃前彻底加热。",
  "self_verify": "",
  "closing": "以后看到类似消息，我们一起查一查。",
  "sources": [],
  "medical_notice": "内容仅供健康信息核验，不能替代医生诊断。"
}
```

### 前端处理建议

- `group_notice` 模式下 `greeting` 预期为空字符串，不要渲染空占位。
- `self_verify` 也可能为空字符串。
- 模型生成内容在展示或分享前，建议允许用户预览和编辑。
- 真实模式下，后端会过滤模型自行生成、但未出现在请求 `sources` 中的 URL。
- 不要依赖每句话一定少于 20 字；这是模型生成要求，不是后端强校验。

### 常见错误

| 状态码 | 场景 |
|---|---|
| `422` | `claim`、`style`、`sources` 等请求字段校验失败 |
| `502` | 模型未配置、调用失败或未返回合法 JSON |
| `500` | 未捕获的模型结构错误或服务异常 |

## 9. 统一错误处理

前端必须兼容三种错误格式。

### 9.1 业务错误：detail 是字符串

```json
{
  "detail": "服务器未安装 FFmpeg，无法从视频抽帧"
}
```

### 9.2 参数错误：detail 是数组

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "claim"],
      "msg": "String should have at least 2 characters",
      "input": "a"
    }
  ]
}
```

### 9.3 未捕获异常：可能不是 JSON

```text
Internal Server Error
```

推荐错误类型：

```ts
interface ValidationErrorItem {
  type: string;
  loc: Array<string | number>;
  msg: string;
  input?: unknown;
  ctx?: Record<string, unknown>;
}

type ApiErrorBody =
  | { detail: string }
  | { detail: ValidationErrorItem[] };
```

推荐解析函数：

```ts
export async function getApiErrorMessage(response: Response): Promise<string> {
  const raw = await response.text();

  try {
    const data = JSON.parse(raw) as ApiErrorBody;

    if (typeof data.detail === "string") {
      return data.detail;
    }

    if (Array.isArray(data.detail)) {
      return data.detail
        .map((item) => {
          const path = item.loc?.slice(1).join(".");
          return path ? `${path}: ${item.msg}` : item.msg;
        })
        .join("；");
    }
  } catch {
    // 返回体不是 JSON，下面使用文本兜底。
  }

  return raw || `请求失败（HTTP ${response.status}）`;
}
```

## 10. 可直接使用的 TypeScript API Client

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL?.replace(/\/$/, "") ?? "";

async function request<T>(
  path: string,
  init: RequestInit = {},
  timeoutMs = 180_000,
): Promise<T> {
  const controller = new AbortController();
  const timer = window.setTimeout(() => controller.abort(), timeoutMs);

  try {
    const response = await fetch(`${API_BASE_URL}${path}`, {
      ...init,
      headers: {
        ...(init.body ? { "Content-Type": "application/json" } : {}),
        ...init.headers,
      },
      signal: controller.signal,
    });

    if (!response.ok) {
      throw new Error(await getApiErrorMessage(response));
    }

    return (await response.json()) as T;
  } catch (error) {
    if (error instanceof DOMException && error.name === "AbortError") {
      throw new Error("请求超时，请稍后重试");
    }
    throw error;
  } finally {
    window.clearTimeout(timer);
  }
}

export const api = {
  health: () => request<HealthResponse>("/health", { method: "GET" }, 10_000),

  extract: (payload: ExtractRequest) =>
    request<ClaimExtraction>(
      "/api/extract",
      { method: "POST", body: JSON.stringify(payload) },
      payload.type === "wechat_url" ? 180_000 : 90_000,
    ),

  verify: (payload: VerifyRequest) =>
    request<VerificationReport>(
      "/api/verify",
      { method: "POST", body: JSON.stringify(payload) },
      120_000,
    ),

  createCard: (payload: CardRequest) =>
    request<VerificationCard>(
      "/api/card",
      { method: "POST", body: JSON.stringify(payload) },
      90_000,
    ),
};
```

补充类型：

```ts
interface HealthResponse {
```

### 完整链路示例

```ts
async function runVerification(input: ExtractRequest) {
  const health = await api.health();

  if (health.mock_mode) {
    console.warn("当前为演示模式，结果可能包含模拟数据");
  }

  const extraction = await api.extract(input);

  // 产品上建议在这里让用户确认或编辑 extraction.claim。
  const report = await api.verify({
    claim: extraction.claim,
    target: "mother",
    relationship_state: "normal",
  });

  const card = await api.createCard({
    claim: report.claim,
    verdict: report.verdict,
    risk_level: report.risk_level,
    summary: report.summary,
    target: "mother",
    style: "elder",
    sources: report.sources,
  });

  return { health, extraction, report, card };
}
```

## 12. 当前后端限制

前端负责人需要了解当前版本的边界：

- 没有用户登录和接口鉴权。
- 没有 SSE/WebSocket 进度推送，所有结果均同步等待后一次性返回。
- 没有服务端任务 ID、历史记录或数据库持久化。
- 没有接口限流、并发控制或请求体大小限制。
- 图片只能通过 JSON Base64/Data URL 提交。
- 公众号视频依赖服务器安装 FFmpeg。
- 外部模型与搜索服务会影响耗时、稳定性和费用。
- `mock_mode=true` 时不能将结果作为真实医学核验依据。
- 本服务只用于健康信息辅助核验，不能替代专业诊断。
