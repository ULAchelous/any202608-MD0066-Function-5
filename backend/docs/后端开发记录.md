## 一、已实现（对照用户体验路径卡 5 步，全部覆盖）

### 核心接口（3 个，真实密钥 + 离线 mock 双模式均已实测通过）

| 接口 | 对应路径卡 | 功能 |
|---|---|---|
| `POST /api/extract` | 第 1、2 步 | 三种输入：公众号链接（解析→下载→**全片均匀抽帧**→视觉模型读帧）、纯文本、截图 Base64。输出核心主张 + 话术标签（夸大因果/恐惧驱动/冒用权威/伪科学术语/情感绑架） |
| `POST /api/verify` | 第 3、4 步 | Tavily 检索权威来源（卫健委/疾控/市监局等白名单域名）→ 生成评估报告：三档结论（credible/misleading/uncertain）、风险等级、来源证据、**四种沟通渠道建议**（私聊/家族群/亲属转达/暂不回应）、共情→事实→建议话术。证据不足强制判 uncertain |
| `POST /api/card` | 第 5 步 | 生成**安心核验卡**：大字短句、非冒犯语气、共情开场、生活化事实、可执行建议、"自己验证"字段（如"你摸摸牙膏底部是不是都有黑条"）、医疗免责声明。支持 `elder`（给长辈）和 `group_notice`（中性群公告版，跨域视角卡方向二）两种风格 |

### 关键工程决策

1. **抽帧策略：全片均匀采样**。ffprobe 取时长后按 `MAX_FRAMES` 均匀铺满全片。旧方案 16帧×3秒只覆盖视频前 48 秒，而谣言核心主张普遍在视频后半段。Qwen3-VL 实测每帧(1280×720)≈922 tokens，24 帧约 2.2 万 tokens，单次成本 ~¥0.006（≤32K 最低档）。
2. **双模式运行**：未配置 LUNA/TAVILY 密钥时自动降级离线 mock（启发式规则，输出带"离线演示"标记），路演现场断网/欠费也能演示；`/health` 返回 `mock_mode` 标识。
3. **渠道兼容**：`response_format=json_object` 不被第三方中转渠道支持时自动降级重试；模型返回的 sources 会过滤掉不在 Tavily 检索结果里的 URL（防幻觉编造链接）。
4. **隐私与安全**：视频下载限 80MB、仅允许 `mp.weixin.qq.com` 域名、抽帧后临时目录自动清理、所有输出强制带医疗免责声明。

### 测试结果（2026-08-05 全绿）

- 单元测试 **8/8 通过**（API 契约、微信解析、核验卡两种风格）
- 离线 e2e：extract(text) → verify → card(elder + group_notice) 全链路通过
- **真实密钥 e2e**：Qwen3-VL-Flash + Tavily 实测通过，"隔夜菜"案例检索到科普中国/市监局等 4 个政府域名来源并生成核验卡

### 实测示例（真实密钥，隔夜菜案例）

```
结论: misleading / 风险: low
来源: 双牌县人民政府(科普中国)、重庆渝中区政府(科普中国)、武昌区政府、泉州市监局
核验卡: "妈，我知道你发这个是为了我们好……" + 冷藏加热建议 + 医疗声明
```

## 二、下一步计划（按优先级，**未做**）

| # | 事项 | 说明 | 依赖 |
|---|---|---|---|
| 1 | **本机/服务器安装 FFmpeg** | 公众号视频链路（路径卡第 1 步的演示亮点）目前因无 FFmpeg 无法实测，`winget install ffmpeg` 即可 | 无，5 分钟 |
| 2 | 公众号视频真实链路实测 | 用路径卡里的真实谣言视频跑通 extract(wechat_url)，调优帧数/成本 | #1 |
| 3 | 核验进度流式返回（SSE） | 路径卡第 3 步要求"正在核验来源→正在交叉比对→正在评估风险"的进度反馈，现在是同步等待 | 无 |
| 4 | 核验卡图片化 | 路径卡第 5 步要"文字/图片卡/语音"，目前只出文字；图片卡需前端渲染或后端出图 | 前端配合 |
| 5 | 用户关系数据存储 | 路径卡第 1 步提到"已储存的用户数据（与长辈关系、语气配置）"，目前每次请求需重传 target/relationship_state | 需定存储方案（SQLite 即可） |
| 6 | 隐私遮挡 | 截图 OCR 前自动打码群名/昵称（路径卡第 2 步要求） | 依赖视觉模型能力或图像处理 |
| 7 | 反馈回传接口 | 路径卡第 5 步"分享后可选填长辈是否接受"，用于路演效果数据（协作分工卡答辩第 1 题要对照数据） | 无，简单 |

### 明确不做（路径卡"不做清单"）

注册/登录、个人中心、深色模式、分享到社交平台。

## 三、给 Android 端的接口约定

- 基础 URL：`http://<服务器>:8000`，文档 `/docs`
- 推荐调用顺序：`/api/extract`（用户确认/修改 claim）→ `/api/verify`（带 target + relationship_state）→ `/api/card`（带 verify 结果 + style）
- 离线 mock 与真实模式返回结构完全一致，前端可先用 mock 联调
